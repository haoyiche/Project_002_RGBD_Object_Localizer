## 2. 核心理论与关键变量

### 2.1 欧氏距离与邻域

对于三维点 $\mathbf p_i=(x_i,y_i,z_i)$ 和 $\mathbf p_j$：

$$
d(\mathbf p_i,\mathbf p_j)=\sqrt{(x_i-x_j)^2+(y_i-y_j)^2+(z_i-z_j)^2}.
$$

`eps` 邻域定义为 $N_\varepsilon(p)=\{q\mid d(p,q)\le\varepsilon\}$，**包含点本身**。`eps` 单位是米，`min_points` 是无量纲整数，表示邻域中至少需要的点数（含自身）。

- **Core**：$|N_\varepsilon(p)|\ge\texttt{min_points}$。
- **Border**：自身不是核心点，但位于某个核心点的 `eps` 邻域中。
- **Noise**：既不是核心点，也未被任何核心点吸收。

**核心点可以扩展密度可达集合，边界点只加入簇，不继续扩展。** 在扫描过程中，暂标为噪声的点，后来仍可能被核心点吸收成为 Border。

**严格概念修正（Boss Test）**：从核心点出发的密度可达具有方向性，末端允许是 Border，但 Border 不能充当继续扩展的中继；密度连通指存在一个点，使两个目标点都从它密度可达。密度连通在一般点集上不能直接当作所有点之间的等价关系：共享边界点可能邻接两个互不连通的核心簇，Border 的最终归属可能依赖实现。实际检查“两个物体是否被合并”时，应优先看 **Core–Core 邻域边组成的连通分量**，而非仅观察任意近点对。跨物体出现近点对是形成跨物体连接的必要但不充分条件（针对两个原本分离的核心点分量）。

**采样密度修正（Boss Test）**：体素下采样后的邻域点数不能直接按 `n_after ≈ n_before × (v/eps)^3` 估算；RGB-D 常采集可见表面，实际邻域数依赖占据体素、原始点密度、形状和位置变化。`eps` 增大通常更易形成 Core，`min_points` 增大通常更难形成 Core，两者不能认为“同增同减效果相似”。三维点云的 `min_points` 也没有固定适用所有场景的数值，须用邻域计数分布与真实验证集标定。

### 2.2 `eps`、`min_points` 的变化规律

| 参数 | 作用 | 过小 | 过大 |
|---|---|---|---|
| `eps` (m) | 搜索邻域的空间半径 | 真实物体可能全部判为噪声 | 原本独立的物体可能密度连接、误合并 |
| `min_points` (int) | 核心点最低邻域点数 | 稀疏背景更容易形成簇 | 下采样后真实物体可能失去核心点 |

注意：`min_points` 改变判定阈值，**不改变坐标和点间距离**；而 EXP031 体素下采样减少点数且可改变质心坐标，因此局部邻域计数可能变化，不能脱离采样密度单独选参数。

### 2.3 Shape / dtype / 数据契约

| 变量 | Shape / 类型 | 说明 |
|---|---|---|
| `points` / `pts` | `(N,3)`，float64 | XYZ 坐标，单位 m；要求数值有限 |
| `diff` | `(N,N,3)`，float64 | 每对点的坐标差 |
| `dist` | `(N,N)`，float64 | 每对点的三维欧氏距离 |
| `neighbor_mask` | `(N,N)`，bool | `dist <= eps` |
| `neighbors` | 长度 N 的索引数组列表 | 每个点的闭邻域 |
| `is_core` | `(N,)`，bool | 是否达到密度阈值 |
| `labels` | `(N,)`，int64 | 未访问内部标记 `-2`；噪声 `-1`；簇 ID 从 0 开始 |

接口约定：`points=(0,3)` 返回空 `int64` 标签；`eps` 必须有限且大于 0；`min_points` 为至少 1 的整数（拒绝 bool）；点坐标不可含 NaN/Inf；单点在 `min_points=1` 时成簇，在 `min_points>=2` 时为噪声。

## 3. 原始 12 点场景与最小实验

物体 A 共 5 点：P00 `(0,0,1.15)`、P01 `(0.02,0,1.15)`、P02 `(0,0.02,1.15)`、P03 `(0.02,0.02,1.15)`、P04 `(0.01,0.01,1.16)`；物体 B 是物体 A 沿 X 平移 0.50 m 后得到的 P05～P09；背景残留 P10 `(0.25,0.25,1.15)`、P11 `(0.90,0.50,1.20)`。

关键距离：$d(P00,P04)=\sqrt3\times0.01\approx0.0173205\,\mathrm{m}$；$d(P00,P01)=0.02000\,\mathrm{m}$。

**最小实验预测/实测**：`eps=0.06 m, min_points=3` 得到两个各 5 点的簇，噪声 P10/P11 共 2 点，Open3D 输出与预测一致。

## 4. A/B/C：三组主动修改实验（预测 → 验证）

### A：只改 `eps`

| 实验 | `eps` | `min_points` | 运行前预测 | Open3D 实测 |
|---|---:|---:|---|---|
| 基线 | 0.060 | 3 | 2 簇，每簇 5 点；噪声 2 | 一致 |
| A1 | 0.015 | 3 | 0 簇，12 噪声 | 一致 |
| A2 | 0.018 | 3 | 2 簇、每簇 5 点；中心为 Core，角点为 Border，噪声 2 | 一致 |

A1：最小不同点间距约 `0.01732 m > eps`，所有点的邻域都只有自身，无法产生核心点。

A2：P04、P09 的邻域各有 5 个点，为 Core；其余 8 个物体角点各只有 2 个邻居，为 Border；P10/P11 为 Noise。**Border 属于簇不要求自身是 Core。**

### B：保持 `eps=0.018 m`，只改 `min_points`

在两组实验中，邻域计数都不变：`[2,2,2,2,5,2,2,2,2,5,1,1]`。

| 实验 | `min_points` | 预测/实测的 Core | 簇 | Noise |
|---|---:|---|---|---:|
| B1 | 5 | P04、P09 | 2 簇，5+5 | 2 |
| B2 | 6 | 无 | 0 簇 | 12 |

结论：门槛从 5 改成 6，即使点云几何完全不变，两个真实物体也可能全部变为噪声。

### C：保持 `eps=0.018 m`、`min_points=3`，只改物体 B 的 X 平移

| 实验 | B 左侧 X | 跨物体邻域边 | Core 数 | 簇结果 | Noise |
|---|---:|---|---:|---|---:|
| C1 | 0.040 m | 无 | 2 | 2 簇，5+5 | 2 |
| C2 | 0.035 m | P01↔P05、P03↔P07 | 6 | 1 簇，10 点 | 2 |

C2 两对跨物体点间距均为 `0.015 m < eps`。P01、P03、P05、P07 从 Border 升级成 Core，加上 P04/P09 构成连通的核心点网络，导致两个独立物体被错误合并。C2 的六个核心点索引为 `[1,3,4,5,7,9]`，边界点为 `[0,2,6,8]`，噪声为 `[10,11]`。**最初预测只考虑 P01↔P05，后续审查补充了对称的 P03↔P07。**

**工程迁移**：误合并会产生跨越两个零件的异常大 AABB，合并质心可能落在两个零件之间。应检测尺寸先验、主轴双峰、连通性和多帧一致性，不宜未经检查把合并簇中心直接发送给机械臂。

### C2 补充订正：相同几何、不同 `min_points` 的核心桥接开关

基于已记录的 C2 NumPy 邻域审计：P00/P02/P06/P08 各 2 点；P01/P03/P05/P07 各 3 点（两条跨物体边分别为 P01↔P05、P03↔P07）；P04/P09 各 5 点；P10/P11 各 1 点。`eps=0.018 m` 固定，P04↔P09 距离为 0.035 m，大于 `eps`。

| `min_points` | Core 点 | 跨物体边两端身份 | 根据邻域图推导的簇结果 | Noise |
|---:|---|---|---|---:|
| 3 | P01/P03/P04/P05/P07/P09 | Core↔Core | 1 簇，10 点 | 2 |
| 4 | P04/P09 | Border↔Border | 2 簇，5+5 | 2 |
| 5 | P04/P09 | Border↔Border | 2 簇，5+5 | 2 |
| 6 | 无 | 无核心点 | 0 簇 | 12 |

**证据性质**：C2 的 `min_points=3` 已由 Open3D 和 NumPy 邻域审计实测；同一 C2 点云在 `min_points=4/5/6` 下的簇数由已验证的邻域计数与 DBSCAN 规则**推导**，这里不冒称新增运行日志。

**最终教训**：同一个物体的点不一定两两位于 `eps` 邻域内。先计算 XYZ 距离 → 统计含自身的邻域点数 → 根据 `min_points` 判定 Core → 再检查 Core 连通分量和 Border 归属。参数从 3 增到 4 时，原本连通的核心桥消失，簇数反而从 1 增到 2；进一步增至 6，所有核心点消失，簇数变为 0。簇数对 `min_points` 不必单调。

## 5. D：NumPy 独立实现与算法理解

源码：`src/experiments/exp033_dbscan_numpy.py`，函数 `dbscan_numpy(points, eps, min_points)`。

核心机制：

1. 验证输入 Shape / 有限性 / 参数；处理空点云。
2. 通过 NumPy 广播计算 `(N,N,3)` 差值和 `(N,N)` 距离；建立 `eps` 邻域列表和核心点布尔数组。
3. 用 `UNVISITED=-2` 与 `NOISE=-1` 区分“尚未检查”和“目前未成簇”。
4. 遇到未访问 Core 开始簇，并把该核心点邻域压入扩展队列；仅核心点的邻域能继续入队。
5. 被暂判为噪声的点即使先前已扫描过，也可被新簇吸收为 Border；保留先前已归属其他簇的 Border 标签。
6. 返回 `(N,)` `int64` 标签。

**具体例子**：三点链 P0=0、P1=0.01、P2=0.02（X，m），`eps=0.011, min_points=3`。邻域数量依次为 2、3、2；先扫描 P0 会暂记 -1，后从 P1(Core) 扩展，P0 被吸收成 Border，最终标签 `[0,0,0]`。

**标签比较**：不同实现可以把簇 ID 0/1 互换；要比较噪声索引集合及簇成员分区（或规范化标签）。ARI 可用于分区相似性，但单用它不能替代精确噪声集合核对。Border 同时邻接两个独立核心簇时，归属可能随访问顺序/实现改变。

**复杂度**：以完整两两距离矩阵实现，时间通常为 $O(N^2)$，空间为 $O(N^2)$。`N=10000` 时，单独的 `(N,N,3)` float64 差值数组约需 2.4 GB（十进制），不适合直接当成大规模点云生产实现。

## 6. E1：数值稳定性 RED → PATCH → GREEN

### 6.1 最小失败场景

旧计算：

```python
dist = np.sqrt((diff * diff).sum(axis=2))
```

| 测试输入 | 真实距离 / 阈值 | 正确结果 | RED 实测错误结果 | 根因 |
|---|---|---|---|---|
| 两点 X 差 `1e155` | 距离 `1e155`，`eps=2e155` | `[0,0]` | `[-1,-1]` | 平方到 `1e310`，float64 上溢为 `inf` |
| 两点 X 差 `1e-200` | 距离 `1e-200`，`eps=5e-201` | `[-1,-1]` | `[0,0]` | 平方到 `1e-400`，float64 下溢为 `0` |

**RED 证据**：2 failed，1 个 `overflow encountered in multiply` 警告（Windows `ai_3d` 实测）。

### 6.2 最小补丁

```python
dist = np.hypot(
    np.hypot(diff[:, :, 0], diff[:, :, 1]),
    diff[:, :, 2],
)
```

保持 `dist.shape=(N,N)` 不变。逐步使用 `hypot` 计算二维及三维欧氏范数，避免本次两个边界场景的中间平方上溢/下溢。仍不能保证任意极端浮点值都安全，例如输入坐标相减本身可能上溢。

## 7. 工程应用与常见误区

| 误区 | 正确认识 | 验证证据 |
|---|---|---|
| 一个 DBSCAN 簇就是一个真实零件 | 密度连接不等于物体语义边界 | C2 合并成 10 点簇 |
| `-1` 一定是错误深度点 | `eps` 过小或 `min_points` 过大可能让真实物体成噪声 | A1、B2 |
| Border 不属于任何簇 | Border 可直接由 Core 吸收 | A2 |
| 首次扫描到 Noise 就永久确定 | 以后可能被 Core 吸收 | D 三点链测试 |
| `min_points` 变大导致点间距离变化 | 它只改变 Core 门槛 | B1/B2 |
| 两个实现的 label 数组必须逐元素一致 | 簇 ID 可置换；需比较实际分区与噪声集合 | D 标签等价性测试 |
| 浮点坐标只要有限，平方距离就一定正确 | 中间平方可能溢出/下溢 | E1 RED/GREEN |
| 手写 O(N²) 版本可以直接处理任意 RGB-D 大场景 | 距离矩阵空间成本很大，需要工程空间索引/分块方案 | Shape 与内存估算 |

## 11. 我的理解与后续强化（依据本人作答整理，已核对）

> 下列内容根据本人在 EXP033 A/B/C/D/E1 实验、Boss Test 及两次补充订正中的**实际文字与推导**整理，并非凭空补写的新实验经历。写入版本不等于已完成人工审阅；提交前需本人检查措辞和结论。

### 11.1 同样变成噪声，`eps=0.015` 和 `min_points=6` 的根因有什么不同？

我现在会先区分**邻域半径**与**邻域计数门槛**：`eps=0.015 m` 时，同一物体内不同点的最近距离约为 `0.01732 m`，任何点的邻域都只有自身，计数为 1，因此 `min_points=3` 下全部成噪声；保持 `eps=0.018 m`、把 `min_points` 提到 6 时，邻域几何关系不变，两个中心点的邻域最多为 5，仍无法成为 Core。前者是“邻域太小，找不到邻居”，后者是“邻居仍在，但门槛超过邻域计数”。

### 11.2 C2 为什么会从 Border 升级为 Core，并导致误合并？

C2 将 B 左侧 X 移到 `0.035 m` 后，有两条跨物体邻域边：P01↔P05、P03↔P07，距离都是 `0.015 m`。这四个点的邻域计数各从 2 增到 3，在 `min_points=3` 时恰好成为 Core，再经 P04/P09 两个中心点形成跨物体的核心点连通路径，因此两个真实物体合并为一个 10 点簇。若只把 `min_points` 提到 4，四个桥接点又都成为 Border，不能中继扩展，两个 5 点物体簇保持分离。**我以后不会把任意“跨物体近点对”直接当成合并的充分条件。**

### 11.3 为什么 `UNVISITED=-2` 与 `NOISE=-1` 不能合并？

`-2` 表示当前尚未检查；`-1` 表示检查时没有达到 Core 要求、目前尚未归簇。这不是同一种状态。三点链 `P0=0、P1=0.01、P2=0.02`，`eps=0.011`、`min_points=3` 时，P0 先被记为 Noise，但之后 P1 作为 Core 启动簇扩展，应把 P0 吸收为 Border。如果把“已经访问”直接当成“不能重新赋值”，会把本来有效的边界点永久误判为噪声。我已在自己实现中用 `-2` 和 `-1` 分开处理，并通过专项 pytest 验证。

### 11.4 E1 的两个 RED 测试为何一个该连却断、另一个该断却连？

旧公式先平方、再求和、再开方。对于 `1e155` 的坐标差，中间平方 `1e310` 超出 `float64` 范围，距离错误变成 `inf`，明明在 `eps=2e155` 内的两点却被分开。对于 `1e-200` 的坐标差，中间平方 `1e-400` 下溢为 0，明明大于 `eps=5e-201` 的两点却被错误合并。我把距离计算改为嵌套 `np.hypot`，新增两项测试由 RED 变 GREEN，原有 29 项与项目全量 160 项测试保持通过。**修复了已复现缺陷，不代表全部浮点边界都已穷尽。**

### 11.5 真实 RGB-D 项目怎样标定聚类参数，并防止错误抓取？

我会从已知真值的单零件、双零件（远/近）场景出发，固定其余条件，分别扫描体素尺寸 `v`、`eps`、`min_points`，并跨多帧记录最近邻距离、邻域计数分布、Core 比例、噪声比例、簇数量、簇大小、质心误差和 AABB 尺寸偏差。下采样会改变占据点数和坐标，原来的 DBSCAN 参数不能不加验证直接继承。若一个簇疑似同时包含两个零件，必须先经过尺寸、点数、形状和多帧一致性门禁；异常状态标记为 `MULTIPLE_OBJECTS_SUSPECTED` 或 `INVALID_CLUSTER`，拒绝直接发布单一抓取位姿，可尝试二次分割和重新校验，失败则跳过本帧并上报。

### 11.6 我对本关的总结

这关真正建立起来的不是一个能运行的 `cluster_dbscan` 调用，而是一套**从几何距离到算法行为再到工程安全检查**的推理链：真实 XYZ 坐标 → `eps` 邻域 → 邻域计数 → Core/Border/Noise → 核心点连通分量 → 簇与三维定位结果。我已经独立复现了参数敏感性、跨物体桥接、Noise 重归类，也完成了 NumPy DBSCAN 和数值稳定性修复。

我曾在补充题中把“同一物体”误当成“两两相邻”，这提醒我：**推理正确不代表前提正确**。以后遇到簇误合并或消失，应先核对坐标、距离、邻域列表、Core 身份，再调参数或改代码，避免拿未经核查的假设解释实验。

### 11.7 仍需强化的内容（从本次错题与后续工程需求提炼）

- **严格概念**：密度可达的方向性、密度连通在共享 Border 情形下的非传递性，以及 Border 在多个簇间的归属差异。
